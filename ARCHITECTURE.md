# Architecture

The design as it is now. Why each part is this shape is in [docs/adr/](docs/adr/README.md);
a change to it goes through an ADR first (PLANNING.md §2). What is checked of it is in
[TESTING.md](TESTING.md) §1; what is still open is in [ROADMAP.md](ROADMAP.md) §3.

## 1. Purpose and scope

brodo holds, edits and stores sparse volumes in three dimensions (signed distance fields,
fluid fields, smoke, temperature) in pure Rust (ADR-0012). It is a part published on its
own and knows nothing of its users.

| User | Use | What it needs from brodo |
| :--- | :--- | :--- |
| a CFD solver | time-stepping fields, stencils | shared topology, neighbour tables, double buffering, leaf-parallel writes, determinism |
| a shape kernel | building, combining and offsetting level sets | tiles, random access, dilation and pruning |
| a process exchanging fields | passing grids between processes | a zero-copy, memory-mappable file |
| `colino` | converting and checking outside shapes | flood fill, connected components, Euler characteristic |

**Out of scope**: level-set operations (CSG, offset, redistancing) and SDF-to-mesh; solvers,
discretisation and linear algebra; visualisation and GUI.

## 2. Crates and layers

| Crate | Contents |
| :--- | :--- |
| `brodo` | The sparse tree, `Topology`, `Field<T>`, `Grid<T>`, topology editing and `Remap`, `LeafManifest`, `ValueAccessor`, leaf-parallel updates and gather, topology analysis, `GridView`, the file profiles, OpenVDB files |
| `colino` | Meshes to narrow-band SDFs on brodo's tree, and the topology report |

## 4. `brodo`

### 4.1 The tree (ADR-0013)

- Four levels: a root `BTreeMap` keyed by coordinate → internal nodes of 32³ → internal
  nodes of 16³ → leaves of 8³ (512 voxels).
- Each node marks its children and tiles by bit masks; offsets come from `count_ones` and
  `trailing_zeros`.
- A **tile** stands for a uniform region in a child's place, without a leaf. The
  **background** is the value outside the tree.
- Nodes live in one arena (`Vec`) per kind, referred to by `u32` index. The concrete node
  types are generated by a macro.
- Voxel coordinates are three `i32`. The world transform (voxel size and affine map) is
  grid metadata.

### 4.2 Topology and fields (ADR-0014)

```rust
pub struct Topology { /* the tree, the leaf list, where tiles are */ }
pub struct Field<T> {
    leaf_values: Vec<T>,   // leaf count × 512, outside the leaves
    tile_values: Vec<T>,   // one per tile
    background: T,
}
```

- Where a tile is belongs to the topology; its value belongs to each field.
- `Grid<T>` binds one `Topology` and one `Field<T>` for single-field use.
- Topology changes (activation, dilation, pruning, splitting and merging tiles) go
  through an editor (`TopologyEditor`) and take effect at `commit`, which returns a
  `Remap` from old to new leaf numbers. Every field on that topology is remapped by it.
- Values are updated and the topology edited in separate phases; while values change, the
  topology is read-only.

### 4.3 Leaf manifest (ADR-0014)

`LeafManifest` is derived from the tree and rebuilt at each `commit`; the tree is the only
source of truth. It holds the leaf coordinates in Morton order, a coordinate-to-leaf
table, and each leaf's 26 neighbour numbers (`NONE` where absent). Leaf numbers, and so the
order of field values, follow Morton order.

### 4.4 Access and parallel work (ADR-0015)

- `ValueAccessor` borrows `&Topology` and `&Field<T>` (or `&mut`), caches the last node
  path for nearby access, and is held one per thread. It serves reads beyond the
  neighbour table.
- The leaf-parallel update (`rayon`) reads the old field by `&` and writes the new field by
  `&mut`, one 512-value chunk per leaf.
- A gather copies a leaf and one ghost layer from its 26 neighbours into a dense 10³
  array, filling missing neighbours with tile or background values.
- Reductions have a fixed-order mode whose result does not depend on the thread count.

### 4.5 Topology analysis

- Flood fill and connected-component labelling on the sparse tree, tiles included, with
  6- or 26-connectivity.
- The Euler characteristic, summed from a table of 2×2×2 local patterns, computable per
  leaf in parallel.
- Dilation and erosion, of topology and values.

### 4.6 Frozen view (ADR-0016)

- `freeze()` packs tree and values into one contiguous byte buffer, read as
  `GridView<'a>` without copying, through `zerocopy`.
- Links between nodes are offsets from the start, in 32-byte units. Every structure is
  32-byte aligned, little-endian, and laid out in `u32` words.

### 4.7 Files (ADR-0016)

| Profile | For | Content | Read by |
| :--- | :--- | :--- | :--- |
| **cache** | passing between processes, replaying frame caches | the `GridView` buffer, uncompressed | memory mapping, no copy |
| **archive** | storing, shipping | metadata, topology and value blocks in compressed chunks of hundreds to thousands of leaves | decompressing chunks, in parallel, into a `GridView` (one copy) |

- Common content: a header (magic number, format version, grid count); per grid, its
  name, value type, voxel size and unit, affine transform, bounding box and free
  key-value metadata; the topology; the values.
- The archive can decompress only the chunks a region needs, and can quantise values
  (16-bit float, 8-bit range), byte-shuffled before compression.
- OpenVDB files (`.vdb`) are read through the `vdb-rs` crate into brodo's tree and written
  by brodo, for level sets and scalar density first.

### 4.8 Value types

`f32`, `f64`, `u8`, `u32` and `[f32; 3]`, bounded by `zerocopy`'s traits, `Copy`, `Send`
and `Sync`.

## 5. `colino` (ADR-0017)

### 5.1 Conversion

- Input: STL (binary and ASCII), OBJ, 3MF, in that order. Badly oriented and holed meshes
  are accepted.
- Distance: exact, to the nearest triangle through a BVH.
- Sign: generalised winding number with a hierarchical approximation; an
  orientation-independent method as an option.
- Output: leaves only in a band of ±N voxels around the surface (N = 3 by default),
  negative tiles inside, the positive background outside. No dense grid: memory follows
  the band's volume, at 3000³ resolution as well.
- It reports changes; it does not repair a shape or refine a grid.

### 5.2 Topology report

| Layer | Content | Method |
| :--- | :--- | :--- |
| 1. Global invariants | β₀, β₁, β₂ of the solid (φ < 0) and of its complement (φ > 0) | β₀: components; β₂: complement components not reaching the outside; β₁ = β₀ + β₂ − χ |
| 2. Labelled connectivity | whether user-labelled regions lie in one complement component | flood fill |
| 3. Local risk | places thinner, or gaps narrower, than two voxels | predicted from the input before conversion, as coordinates and extents |

- Reference for layer 1: the genus from the input's V − E + F when the mesh is a closed
  manifold; otherwise a local reconversion of the risky places at h/2, whose invariants
  must agree.
- The report is a `serde`-serialisable structure: what may have changed, where, and by how
  much.

## 6. Compatibility

- Before 1.0 the API may break; every break is in CHANGELOG.md (TESTING.md V3), and users
  pin a git revision.
- The `GridView` layout and each file profile have their own format version (TESTING.md
  V6).
