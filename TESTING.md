# Testing

> **Phase: verification.** What must pass before a change lands. The mechanical checks are
> in [AUDITING.md](AUDITING.md).

## 1. Tiers

| Tier | What | Where | Tolerance |
| :--- | :--- | :--- | :--- |
| **Unit** | One function or type, on input small enough to work out by hand | `#[cfg(test)] mod tests` at the end of the file | exact, or stated in the test |
| **Integration** | A crate's public API, or several crates together, on realistic input | `crates/*/tests/` | stated per test (T4) |
| **Reference** | Property tests against a dense reference implementation written in the test itself: random activation and writes give the same values; topology edits keep every field's values through `Remap`; every leaf's 26 neighbours match those computed from coordinates | `crates/*/tests/` | exact |
| **Format** | `freeze` and each file profile: a write then a read gives the same bits, and the same input gives the same bytes at any thread count | `crates/*/tests/` | exact, by bits |
| **Image** | The checking output (ARCHITECTURE.md §6.1): slices of a sphere's SDF, a torus's SDF and a field with tiles, compared with committed golden images as decoded pixels, so that a change of encoder does not fail them; the same input gives the same PNG bytes | `crates/brodo/tests/` | exact, by pixel |
| **GPU** | `piatto`, if built (ARCHITECTURE.md §6.2): a `GridView` buffer copied to the GPU as it is, values at known voxels read back by a shader and compared; `#[ignore = "needs a GPU"]` where none is | `crates/piatto/tests/` | exact, by bits |
| **Benchmark** | Activation, random access, the leaf-parallel update, gather, `freeze`, file I/O; their baselines are kept with the benchmarks, dated, with the hardware model they ran on (never a host name) | `crates/*/benches/` | T5 |

The shapes colino is checked on (sphere, torus, double torus, holed meshes, walls thinner
than a voxel) are generated by the tests, not committed as files.

## 2. Rules

| Rule | Requirement | Enforced by |
| :--- | :--- | :--- |
| **T1** | No standalone test file in `src/`. A test is `#[ignore]`d only as `#[ignore = "needs …"]`, directly or under `cfg_attr`, naming something the repository does not hold | `scripts/audit/source.py --ignores`, however the attribute's lines break, in every target (ADR-0021); that the repository lacks what it names, **nothing** |
| **T2** | A tolerance is never loosened, and a test never deleted or disabled, without an ADR (PLANNING.md §2); one that holds more than a promise (T12) is brought to it under ADR-0043 | a test deleted or renamed: `scripts/audit/tests.py` holds every test to its crate's `test-list.txt`, and the `commit-msg` hook asks an ADR of a commit that removes a line from one (ADR-0022); a tolerance loosened, **nothing**; review the diff of every test and tolerance |
| **T3** | A new test is shown to fail against the defect it guards: break the code, watch it fail at the assertion that guards that defect, not at an error or panic elsewhere, restore. The break is larger than any tolerance the test applies, or it cannot fail. The break is checked to change what the code computes, and each test target it may affect is run on its own, since `cargo test` stops at the first target that fails (ADR-0020) | nothing |
| **T4** | A tolerance is a named constant defined once (per tier, or per test data set), never a literal at the comparison, so that T2's review reads one line | nothing |
| **T5** | A performance comparison takes the fastest of many runs of each variant, the variants run in turn, each run from evicted caches, each comparison in a fresh process, a benchmark's on as many threads as the machine has performance cores; it is run twice and states how far the runs agree, and a pair whose runs disagree on an item by more than 10 % is refused, neither judged nor recorded (ADR-0019) | the refusal and the threads, the benchmark harness (`crates/brodo/benches/harness/mod.rs`); a spike's timing, **nothing** |
| **T6** | Every module that parses untrusted bytes (`UNTRUSTED_INPUT`) has a fuzz target in `fuzz/` for each way in which it reads them (ADR-0006, ADR-0009). Before a milestone closes, every target runs 900 s with no finding (§3); a finding becomes a test that fails without its fix (T3), then is fixed | `scripts/audit/workspace.py`: `fuzz/` exists, stays outside the workspace, and depends on each such module's crate; a target per way in, and the run, **nothing**; the milestone's checklist in ROADMAP.md lists the run |
| **T7** | Before a milestone closes, the tests named `miri_*`, which take each path through unsafe code in the workspace crates' dependencies, on a grid of a few leaves or a package of a few triangles, pass under Miri (§3): those on one thread under Stacked Borrows, those on several threads under Tree Borrows. The file in `UNSAFE_MODULES` is not run, since Miri cannot map a file (ADR-0008) | nothing; the milestone's checklist in ROADMAP.md lists the run |
| **T8** | A change to values or topology is also checked by eye: the change writes a slice of an affected field as PNG (ARCHITECTURE.md §6.1), and whoever made it, agent or human, looks at the image before the change lands, for what numbers miss: a sign flipped, a hole where a tile should be, a seam between leaves (ADR-0018). From when the checking output exists | nothing |
| **T9** | A test over generated cases (a property test) is shown to reach the cases it is meant for: the commit that adds or changes it counts, by instrumentation removed before the commit, how many cases reached each kind of input the test names, and states the counts in its message. A kind reached by under 1 % of the cases is built by the generator, not left to chance (ADR-0020) | nothing |
| **T10** | A change to a crate's `src/` on a path one of its benchmarks times is benchmarked before it lands, on a machine at rest (`cargo bench -p <crate> --bench <crate> --all-features`, every item behind a feature included), and does not land while an item fails its baseline; the commit states the result in a line beginning `Benchmarks`, or says `Benchmarks: not on a timed path` (ADR-0019) | `commit_msg_check.py`, in the hook and the audit: a commit changing the `src/` of a crate with a benchmark has such a line; in the hook, unless it says the path is not timed, the crate's `out/bench/<crate>/report.tsv` newer than each staged file of its `src/`, every item `ok`; whether the path is timed and the machine at rest, **nothing** |
| **T11** | Before a milestone closes, every mutant cargo-mutants makes of the workspace is run, through `scripts/audit/mutants.py --run` (§3) and never without it, with every feature as the gate's tests are: it puts `rss_guard.py` in front of each test binary, which kills it and every process descended from it once together they pass 1 GiB, since macOS enforces no memory limit and an endless mutant took the machine down. The run passes when its unmutated baseline passes, the guard logged each run, every mutant listed is reported, a list of none failing and a sharded run's reports held to the whole list by `--report … --`, no mutant is missed and every timeout follows a failed test, or, run again by `mutants.py --run --patient` under a timeout of 1800 s, is caught; one whose tests then all pass is only slower, and is excluded as equivalent with that reason. A missed mutant whose difference breaks a promise (T12) is killed by a new test (T3); one equivalent under the contract is excluded in `.cargo/mutants.toml` with the human's approval, under a comment saying why and ending in its kind: `[same]`, the same result for every input; `[open: WHERE]`, a difference only where a promise leaves the result open, a bound, rounding, an order or a tie; `[unreached: WHERE]`, a difference only on input a documented limit refuses; WHERE a promise's home (AGENTS.md), `ARCHITECTURE.md §N`, `docs/formats.md §N` or a public item's path in backticks, whose text says so in words, "not promised" or "refused"; silence leaves nothing open. The file holds those exclusions only, and the run's settings are in `mutants.py` (ADR-0023, ADR-0043) | `scripts/audit/mutants.py`: the run's verdict, of its baseline, the guard's log, every mutant listed and each one's outcome; in the audit, the file holds no setting, and every exclusion has its reason, its kind and where, a section that exists or a public item, whose text has the kind's words, and matches a mutant; whether the kind is true, **nothing**; that the run is made, **nothing**; the milestone's checklist in ROADMAP.md lists the run |
| **T12** | A test asserts what a promise states (its homes, AGENTS.md), or what a reference computation in the test gives. A unit test of a private item holds it to its documentation only where a public promise rests on it, the test's documentation naming that promise. A behaviour worth holding that no document states is written into one first, in the same commit. A tolerance is no tighter than the promise it checks, unless the test says why; where several broken rules could be named, the test breaks one, unless the order is a promise (ADR-0043) | nothing; review every new assertion against the promise it names |
| **T13** | A check docs/formats.md gains for a reader is added to `scripts/audit/formats.py` in the same commit, so that the gate holds every golden file already there to it before any code reads it, and a rule misstated is found when it is written (ADR-0037) | the gate's `format_document.rs`, once the check is in `formats.py`; that it is added in the same commit, **nothing** |
| **T14** | Before a version that promises its API stays, 1.0 and each MAJOR after it, each crate, and `mestolo`'s command line, is surveyed for what it lacks against its promises' homes (AGENTS.md), by running it: a promise not kept, an operation without its counterpart, a use its users would need that only internals give. Each gap is taken before the version, or recorded in ROADMAP.md as one a later MINOR adds without breaking a user (ADR-0033) | nothing; the milestone's checklist in ROADMAP.md lists the survey |

T6's, T7's and T11's runs at a milestone's close are held at every milestone through P4,
and T14's survey at every one that sets such a version;
from P5 on, the human chooses those a milestone closes with by its content, and its
checklist in ROADMAP.md lists them (ADR-0033).

## 3. Running

```bash
cargo test --workspace --all-features                       # the tests alone, as the gate runs them
cargo test --workspace --all-features -- --include-ignored  # also what needs a look, or VTK
```

The fuzzer (T6) needs a nightly toolchain and `cargo install cargo-fuzz`. Its manifest,
`fuzz/Cargo.toml`, is written by hand rather than by `cargo fuzz init`, which at a virtual
workspace's root points the dependency at the root and leaves out `[workspace]`:

```toml
[package]
name = "fuzz"
version = "0.0.0"
edition = "2024"
publish = false

[package.metadata]
cargo-fuzz = true

[dependencies]
libfuzzer-sys = "<the current version, looked up>"
<crate> = { path = "<crates/<crate>, relative to fuzz/>" }

# Its own workspace, so cargo does not look for it in the one above.
[workspace]
members = ["."]

[[bin]]
name = "<target>"
path = "fuzz_targets/<target>.rs"
test = false
doc = false
bench = false
```

Each target, from the root:

```bash
cargo +nightly fuzz run --fuzz-dir fuzz -a -O <target> -- -max_total_time=900 -timeout=60 -rss_limit_mb=2048
```

`-a` keeps debug assertions on, so an overflow is a finding rather than a wrapped value. A
finding is a non-zero exit and an input written under `fuzz/artifacts/<target>/`.

A target whose input has a structure random bytes rarely reach, a cache file, a frozen
grid, a set of Hermite data, a 3MF package, starts from the committed files under
`crates/brodo/tests/data/` and `crates/colino/tests/data/` as seeds, copied into
`fuzz/corpus/<target>/` before the run.

Miri (T7) needs `rustup +nightly component add miri`. Isolation is off, since the tests
read files; the leak check is off for the threaded test, since rayon's threads outlive it:

```bash
MIRIFLAGS="-Zmiri-disable-isolation" cargo +nightly miri test -p brodo --test miri_paths -- miri_a_
MIRIFLAGS="-Zmiri-disable-isolation -Zmiri-tree-borrows -Zmiri-ignore-leaks" cargo +nightly miri test -p brodo --test miri_paths -- miri_the_
cargo +nightly miri test -p colino --test miri_paths -- miri_
```

Mutation testing (T11) needs `cargo-mutants`, which the audit also needs, at the version
`.github/workflows/audit.yml` installs, the one home of each tool's version, which the
gate holds the running one to (27.1.0 on 2026-11-07; ADR-0034); so is `cargo-nextest`,
which a run on GitHub Actions may be given to run each mutant's tests (ADR-0034). The run's settings (jobs, timeout, guard, output) are in
`scripts/audit/mutants.py`, the equivalent mutants in `.cargo/mutants.toml`. The run
takes hours: about 9 for the workspace's 4247 mutants (`cargo mutants --workspace
--all-features --list | wc -l`, 2026-11-02) at the two jobs `mutants.py` runs, from 13 to
16 s a caught mutant (ADR-0023). Run it at rest, with nothing else running:

```bash
python3 scripts/audit/mutants.py --run                                  # the milestone's run
python3 scripts/audit/mutants.py --run -f crates/brodo/src/tree.rs      # one file
python3 scripts/audit/mutants.py --run --iterate                        # skip what was caught
python3 scripts/audit/mutants.py --run --patient                        # the last run's timeouts, again
python3 scripts/audit/mutants.py --report out/mutants/mutants.out       # judge a report again
python3 scripts/audit/mutants.py --report shards/*/mutants.out --       # a sharded run's reports, every mutant
python3 scripts/audit/mutants.py --run --patient --from shards/*/mutants.out  # their timeouts, again
python3 scripts/audit/mutants.py --run --patient --from shards/*/mutants.out -- --shard 3/20  # a twentieth
```

A mutant applied by hand, to show that a test fails on it (T3), runs behind the same
guard, as cargo's runner for the host's target (on macOS, as below), since such a mutant can grow without bound as a run's can; held
by nothing (ADR-0023):

```bash
CARGO_TARGET_AARCH64_APPLE_DARWIN_RUNNER=$PWD/scripts/audit/rss_guard.py RSS_GUARD_MIB=1024 \
  RSS_GUARD_LOG=$PWD/target/hand-mutants-guard.log cargo test -p colino --lib thin
```

The check of a release's API (V9) needs `cargo-semver-checks` at the version `audit.yml`
installs, 0.51.0, which reads the rustdoc JSON, format 60, of the toolchain
`rust-toolchain.toml` pins (measured 2026-11-07); a toolchain pin raised is measured against it again. The gate runs
it, from 1.0, in about 20 s with its builds cached and 2 min without (2026-11-07, a
scratch tag `v1.0.0`); by hand:

```bash
python3 scripts/audit/semver.py                                          # as the gate runs it
cargo semver-checks --workspace --baseline-rev v0.9.0 --all-features     # the breaks since a tag, before 1.0 too
```

On GitHub Actions, `.github/workflows/mutants.yml`, started by hand, runs 160 shards and
the timeouts again in 20 parts, each part holding the shards' reports to every mutant
listed (ADR-0034).

## 4. Before a change lands

| Check | Requirement |
| :--- | :--- |
| `./scripts/audit/verify_compliance.sh` | ends `=== AUDIT PASSED ===`. It runs the tests as its last step. Run it with no edit in flight |
| ROADMAP.md §1 | updated (PLANNING.md §1) |
| The last push's run on GitHub Actions | read before the next commit lands, every job; one failed is fixed first, the failure recorded where its cause's rule lives (ADR-0034). Held by **nothing**: the gate needs no GitHub access |

The gate also runs on GitHub Actions after each push to `main` (ADR-0034), and its tests
on macOS (arm64) and Windows (x86-64) as well; the run on the owner's machine before the
push is the one a change lands on.

## 5. Versions

| Rule | Requirement | Enforced by |
| :--- | :--- | :--- |
| **V1** | The version is `MAJOR.MINOR.PATCH`, with no pre-release or build part, `0.MINOR.PATCH` before 1.0, written once, in the workspace `Cargo.toml`; every crate takes `version.workspace = true`, so that brodo, colino and mestolo are released together at one version (ADR-0011) | `scripts/audit/workspace.py`, the inheritance and the form, cargo refusing what is not semantic versioning's |
| **V2** | Closing a milestone (ROADMAP.md §2) raises MINOR: P0 gives 0.1.0, P1 0.2.0. A change that only fixes the last version raises PATCH. Between milestones, a small release raising MINOR is cut when a user needs a change before its milestone closes, the gate its only check (ADR-0040). Until 1.0 a MINOR may break the API. From 1.0 a version follows semantic versioning over the promises, of AGENTS.md's three homes and of `mestolo`'s command line and output as ARCHITECTURE.md §6.3 states them, an item under `#[doc(hidden)]` promising nothing: a release breaking one raises MAJOR, a closing milestone's or a small release's among them, one adding to them MINOR, and one only fixing the last version PATCH (ADR-0011) | from 1.0, what V9's check sees; the rest, **nothing** |
| **V3** | CHANGELOG.md has a section per version, newest first, headed `## <version> (<date>)`, with the milestones it closed and every change that breaks a user; its newest is the version `Cargo.toml` states (0.0.0 while there is none). A breaking change is added under `## Unreleased` in the commit that makes it | `scripts/audit/workspace.py` for the version; the entries, **nothing** |
| **V4** | The commit that sets a version passes the gate (§4), and on GitHub Actions the gate and its tests on macOS and Windows (§4), and carries the local tag `v` + the version. Once the tag is pushed, a GitHub release of it is made, titled with the version, its notes the version's CHANGELOG.md section (ADR-0040). From 1.0 each crate is then published to crates.io, brodo, then colino, then mestolo, by the owner running `cargo publish` on the owner's machine; an agent runs `cargo publish --dry-run` alone (ADR-0040) | nothing |
| **V5** | 1.0 is the human's decision, recorded in an ADR | nothing |
| **V6** | The `GridView` byte layout and each file profile carry a format version of their own, independent of the crate version, raised by any change to the bytes and recorded in CHANGELOG.md with which older versions still read. A release that raises one still reads the version before it, and can write it on request; older ones are refused, the error naming them (ADR-0038). Before 1.0 alone, the owner may set this aside for a format, in an ADR, its earlier versions then refused as older ones are (ADR-0053) | the Format-tier tests comparing written bytes with the committed files of docs/formats.md §7 |
| **V7** | The workspace's `rust-version` is raised only by a release raising MAJOR or MINOR, never PATCH, and its CHANGELOG.md section says so (ADR-0011) | `scripts/audit/workspace.py`: a version whose PATCH is above 0 states the `rust-version` of tag `vMAJOR.MINOR.0`; the CHANGELOG.md entry, **nothing** |
| **V8** | Each crate is published to crates.io alone, `publish = ["crates-io"]` set once in the workspace `Cargo.toml` and taken by `publish.workspace = true`; the workspace's dependency on brodo states the workspace version as well as its path, so that colino and mestolo depend on the brodo released with them, by a range resolving to one copy; and each package holds its `Cargo.toml`, README.md, `LICENSE-APACHE` and `LICENSE-MIT`, the root's bytes, `src/` and `examples/`, and nothing else, its tests, benchmarks and their data left out (ADR-0040) | `scripts/audit/workspace.py`, reading `cargo package --list`; the keywords, categories and docs.rs's features, **nothing** |
| **V9** | From 1.0, the code breaks no promise of the last release beyond what the workspace version allows (V2). The baseline is the newest release tag merged into HEAD; while it and the workspace version are 1.0 or above and of one MAJOR, each crate's library keeps the baseline's API, by cargo-semver-checks, with no feature, each feature alone and every feature, and the baseline's `crates/mestolo/tests/` pass on the current code. A break made for the next MAJOR is declared by `### Breaking` under CHANGELOG.md's `## Unreleased`, which suspends the check until that version, and a version whose section has `### Breaking` raises MAJOR. What the tool does not see, a type changed, a bound or a lifetime narrowed, a constant's value, a behaviour no test holds, is held by review (ADR-0011) | `scripts/audit/semver.py`, and the gate's `[Tools]` step the tool's version; what the tool misses, **nothing** |
