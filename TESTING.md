# Testing

> **Phase: verification.** What must pass before a change lands. The mechanical checks are
> in [AUDITING.md](AUDITING.md).

## 1. Tiers

| Tier | What | Where | Tolerance |
| :--- | :--- | :--- | :--- |
| **Unit** | One function or type, on input small enough to work out by hand | `#[cfg(test)] mod tests` at the end of the file | exact, or stated in the test |
| **Integration** | A crate's public API, or several crates together, on realistic input | `crates/*/tests/` | stated per test (T4) |
| **Reference** | Property tests against a dense reference implementation written in the test itself: random activation and writes give the same values; topology edits keep every field's values through `Remap`; every leaf's 26 neighbours match those computed from coordinates | `crates/*/tests/` | exact |
| **Format** | `freeze` and each file profile: a write then a read gives the same bits, and the same input gives the same bytes at any thread count | `crates/*/tests/` | exact, by bits |
| **Image** | The checking output (ARCHITECTURE.md §6.1): slices of a sphere's SDF, a torus's SDF and a field with tiles, compared with committed golden images as decoded pixels, so that a change of encoder does not fail them; the same input gives the same PNG bytes | `crates/brodo/tests/` | exact, by pixel |
| **GPU** | `piatto` (§6.2): a `GridView` buffer copied to the GPU as it is, values at known voxels read back by a shader and compared; `#[ignore = "needs a GPU"]` where none is | `crates/piatto/tests/` | exact, by bits |
| **Benchmark** | Activation, random access, the leaf-parallel update, gather, `freeze`, file I/O; their baselines are kept with the benchmarks, dated, with the hardware model they ran on (never a host name) | `crates/*/benches/` | T5 |

The shapes colino is checked on (sphere, torus, double torus, holed meshes, walls thinner
than a voxel) are generated by the tests, not committed as files.

## 2. Rules

| Rule | Requirement | Enforced by |
| :--- | :--- | :--- |
| **T1** | No standalone test file in `src/`. A test is `#[ignore]`d only as `#[ignore = "needs …"]`, directly or under `cfg_attr`, naming something the repository does not hold | the audit, in every target (ADR-0021) |
| **T2** | A tolerance is never loosened, and a test never deleted or disabled, without an ADR (PLANNING.md §2) | a test deleted or renamed: `scripts/audit/tests.py` holds every test to its crate's `test-list.txt`, and the `commit-msg` hook asks an ADR of a commit that removes a line from one (ADR-0022); a tolerance loosened, **nothing**; review the diff of every test and tolerance |
| **T3** | A new test is shown to fail against the defect it guards: break the code, watch it fail at the assertion that guards that defect, not at an error or panic elsewhere, restore. The break is larger than any tolerance the test applies, or it cannot fail. The break is checked to change what the code computes, and each test target it may affect is run on its own, since `cargo test` stops at the first target that fails (ADR-0020) | nothing |
| **T4** | A tolerance is a named constant defined once (per tier, or per test data set), never a literal at the comparison, so that T2's review reads one line | nothing |
| **T5** | A performance comparison takes the fastest of many runs of each variant, the variants run in turn, each run from evicted caches, each comparison in a fresh process; it is run twice and states how far the runs agree | nothing |
| **T6** | Every module that parses untrusted bytes (`UNTRUSTED_INPUT`) has a fuzz target in `fuzz/` for each way in which it reads them (ADR-0006, ADR-0009). Before a milestone closes, every target runs 900 s with no finding (§3); a finding becomes a test that fails without its fix (T3), then is fixed | `scripts/audit/workspace.py`: `fuzz/` exists, stays outside the workspace, and depends on each such module's crate; a target per way in, and the run, **nothing**; the milestone's checklist in ROADMAP.md lists the run |
| **T7** | Before a milestone closes, the tests named `miri_*`, which take each path through unsafe code in the workspace crates' dependencies, on a grid of a few leaves or a package of a few triangles, pass under Miri (§3): those on one thread under Stacked Borrows, those on several threads under Tree Borrows. The file in `UNSAFE_MODULES` is not run, since Miri cannot map a file (ADR-0008) | nothing; the milestone's checklist in ROADMAP.md lists the run |
| **T8** | A change to values or topology is also checked by eye: the change writes a slice of an affected field as PNG (ARCHITECTURE.md §6.1), and whoever made it, agent or human, looks at the image before the change lands, for what numbers miss: a sign flipped, a hole where a tile should be, a seam between leaves (ADR-0018). From when the checking output exists | nothing |
| **T9** | A test over generated cases (a property test) is shown to reach the cases it is meant for: the commit that adds or changes it counts, by instrumentation removed before the commit, how many cases reached each kind of input the test names, and states the counts in its message (ADR-0020) | nothing |
| **T10** | A change to a crate's `src/` on a path one of its benchmarks times is benchmarked before it lands, on a machine at rest (`cargo bench -p <crate> --bench <crate>`), and does not land while an item fails its baseline; the commit states the result (ADR-0019) | nothing |
| **T11** | Before a milestone closes, every mutant cargo-mutants makes of the workspace is run, through `scripts/audit/mutants.py --run` (§3) and never without it: it puts `rss_guard.py` in front of each test binary, which kills it and every process descended from it once together they pass 1 GiB, since macOS enforces no memory limit and an endless mutant took the machine down. The run passes when no mutant is missed and every timeout follows a failed test. A missed mutant is killed by a new test (T3), or, when no test can tell it from the original, excluded in `.cargo/mutants.toml` under a comment saying why; the file holds those exclusions only, and the run's settings are in `mutants.py` (ADR-0023) | `scripts/audit/mutants.py`, in the audit: the file holds no setting, and every exclusion has its reason and matches a mutant; the run, **nothing**; the milestone's checklist in ROADMAP.md lists the run |

## 3. Running

```bash
cargo test --workspace --all-features                       # the tests alone, as the gate runs them
cargo test --workspace --all-features -- --include-ignored  # also what needs local files
```

The fuzzer (T6) needs a nightly toolchain and `cargo install cargo-fuzz`. Its manifest,
`fuzz/Cargo.toml`, is written by hand rather than by `cargo fuzz init`, which at a virtual
workspace's root points the dependency at the root and leaves out `[workspace]`:

```toml
[package]
name = "fuzz"
version = "0.0.0"
edition = "2024"
publish = false

[package.metadata]
cargo-fuzz = true

[dependencies]
libfuzzer-sys = "<the current version, looked up>"
<crate> = { path = "<crates/<crate>, relative to fuzz/>" }

# Its own workspace, so cargo does not look for it in the one above.
[workspace]
members = ["."]

[[bin]]
name = "<target>"
path = "fuzz_targets/<target>.rs"
test = false
doc = false
bench = false
```

Each target, from the root:

```bash
cargo +nightly fuzz run --fuzz-dir fuzz -a -O <target> -- -max_total_time=900 -timeout=60 -rss_limit_mb=2048
```

`-a` keeps debug assertions on, so an overflow is a finding rather than a wrapped value. A
finding is a non-zero exit and an input written under `fuzz/artifacts/<target>/`.

Miri (T7) needs `rustup +nightly component add miri`. Isolation is off, since the tests
read files; the leak check is off for the threaded test, since rayon's threads outlive it:

```bash
MIRIFLAGS="-Zmiri-disable-isolation" cargo +nightly miri test -p brodo --test miri_paths -- miri_a_
MIRIFLAGS="-Zmiri-disable-isolation -Zmiri-tree-borrows -Zmiri-ignore-leaks" cargo +nightly miri test -p brodo --test miri_paths -- miri_the_
cargo +nightly miri test -p colino --test miri_paths -- miri_
```

Mutation testing (T11) needs `cargo install --locked cargo-mutants@27.1.0`, which the
audit also needs. The run's settings (jobs, timeout, guard, output) are in
`scripts/audit/mutants.py`, the equivalent mutants in `.cargo/mutants.toml`. The run
takes hours: about 5 for brodo's 1099 mutants at one job, from 16.5 s a mutant measured
on 2026-10-18 (ADR-0023). Run it at rest, with nothing else running:

```bash
python3 scripts/audit/mutants.py --run                                  # the milestone's run
python3 scripts/audit/mutants.py --run -f crates/brodo/src/tree.rs      # one file
python3 scripts/audit/mutants.py --run --iterate                        # skip what was caught
python3 scripts/audit/mutants.py --report out/mutants/mutants.out       # judge a report again
```

## 4. Before a change lands

| Check | Requirement |
| :--- | :--- |
| `./scripts/audit/verify_compliance.sh` | ends `=== AUDIT PASSED ===`. It runs the tests as its last step. Run it with no edit in flight |
| ROADMAP.md §1 | updated (PLANNING.md §1) |

There is no hosted CI; this gate, run locally, is the CI.

## 5. Versions

| Rule | Requirement | Enforced by |
| :--- | :--- | :--- |
| **V1** | The version is `0.MINOR.PATCH`, written once, in the workspace `Cargo.toml`; every crate takes `version.workspace = true` | `scripts/audit/workspace.py` |
| **V2** | Closing a milestone (ROADMAP.md §2) raises MINOR: P0 gives 0.1.0, P1 0.2.0. A change that only fixes the last version raises PATCH. Until 1.0 a MINOR may break the API | nothing |
| **V3** | CHANGELOG.md has a section per version, newest first, headed `## <version> (<date>)`, with the milestones it closed and every change that breaks a user; its newest is the version `Cargo.toml` states (0.0.0 while there is none). A breaking change is added under `## Unreleased` in the commit that makes it | `scripts/audit/workspace.py` for the version; the entries, **nothing** |
| **V4** | The commit that sets a version passes the gate (§4) and carries the local tag `v` + the version | nothing |
| **V5** | 1.0 is the human's decision, recorded in an ADR | nothing |
| **V6** | The `GridView` byte layout and each file profile carry a format version of their own, independent of the crate version, raised by any change to the bytes and recorded in CHANGELOG.md with which older versions still read | a Format-tier test comparing written bytes with a committed file, once the format exists (ROADMAP.md, P1) |
