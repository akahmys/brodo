# ADR-0013: The tree has four fixed levels with tiles, nodes in arenas, and a BTreeMap root

- **Status**: Amended
- **Date**: 2026-10-16

## Context

A shallow, wide tree (Museth, 2013) gives near-constant access and leaves uniform regions
cheap. Boxing each node scatters memory. Stable Rust cannot compute array lengths from
const generics (`generic_const_exprs` is unstable). A hash-map root, as the design first
proposed, iterates in an order that varies between runs, which CODING.md Rule 6 forbids.

## Decision

- Levels: a root map, internal nodes of 32³ and 16³, leaves of 8³ (512 voxels). Each node
  marks children and tiles with bit masks, offset by `count_ones` and `trailing_zeros`.
- Tiles hold uniform regions without leaves; the background value lies outside the tree.
- Nodes live in one arena (`Vec`) per kind and are referred to by `u32` index.
- Concrete node types are generated by a macro.
- The root is a `BTreeMap` keyed by coordinate. A hash map is considered again only if a
  spike measures root lookups as a bottleneck.
- Voxel coordinates are three `i32`; the world transform (voxel size, affine map) is grid
  metadata.

## Consequences

Root iteration is deterministic. Root lookups cost O(log n) in the number of top-level
nodes, which is small.

## Amendment

- **Date**: 2026-10-17

Two points the design left silent were decided by the human before the minimal tree was
built.

- A leaf holds no per-voxel active state: every voxel of a leaf is active. This matched
  the design as written and the remap spike. Whether dilation, erosion and flood fill need
  a per-voxel mask was recorded as B-011, to be answered before them.
- Activating a voxel inside a tile changes nothing, since a tile's region is active
  already. A tile becomes leaves only by an explicit split, which turns each level on the
  path into a node whose other children are tiles, down to one leaf.
